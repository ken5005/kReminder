## 0. この文書の背景

- 旧版のメイン画面（`SceduleFrame`）は「リスト＋大量のツールバーボタン、ダブルクリックで編集サブウインドウ」という作りだった。これは想定どおり。
- ただし**表示フィルタの論理が破綻していた**。旧 `SceduleTableModelSorter` の中に判定が埋め込まれ、「表示を足す」トグルと「表示を隠す」トグルが同じ関数で混在。作者自身がコードに `//このへんわけわかめ` と書き残していた。→ 本仕様の主眼は**このフィルタを1つのモデルに再設計すること**。
- 旧コードは**移植しない**。要件（列構成・フィルタの意図・通知エスカレーション・スヌーズ機構）だけサルベージし、クリーンに組み直す。設計思想5原則（v0 §9）を踏襲。

## 2. メイン画面（予定表）

### 2.1 全体構成

- 単一ウィンドウ。上部にツールバー、その下にリスト（`JTable` + `JScrollPane`）。
- 旧版はコントロールパネルの1サブフレームだったが、kReminder では**これがメイン画面**。将来 kClock2 と統合する際は、アイコン／ダブルクリック等でこの操作ウィンドウを開く（統合は後フェーズ・v0 §1）。

### 2.2 ツールバー — 「高頻度操作だけトップレベル」方針

**恒久方針：トップレベル（ツールバー）には高頻度な操作だけを置く。低頻度・雑多な操作は右クリックメニューへ逃がす。** 今後機能を足すときも、高頻度でなければデフォルトで右クリック行き。

- **ツールバー（トップレベル）**：`新規` / `編集` / `複製` / `削除` ＋ **フィルタ群（トグルボタン）** ＋ **検索ボックス**
- **右クリックメニュー（行の上）**：`音試験` / （今後の雑多機能）
- 編集は**ダブルクリックでも**開ける（ツールバーの `編集` と等価）。

（v2→新規/複製/削除スライスでの変更：`複製` は当初この右クリック行きの想定だったが、実運用者の実測で新規と同程度に高頻度と判明したためツールバー＋キーバインド（Ctrl+D）に格上げした。§8 決定事項ログに追記。）

フィルタ群を高頻度としてトップレベルに置くのは、実運用者本人が「フィルタは頻繁に切り替えていた・浅い階層にある方が気持ちよかった」と記憶しているため（実測優先）。

### 2.3 リスト（6列）

旧版5列に、kReminder のデータモデル（v0 §2）に合わせて **action 列を追加して6列**。

| # | 列名 | 中身 | ソート |
|---|---|---|---|
| 0 | Type | 優先度番号（`5`〜`1`）。`Pri-` は落として数字だけ表示 | 独自比較（下記） |
| 1 | リピート | `repeat` を日本語化した文字列（例: 「毎日 日土を除く」） | 文字列 |
| 2 | 次回実行 | `fireAt` を `yyyy/MM/dd(曜) HH:mm[:ss]` 形式に整形（`FireAtFormat.forList`）。秒が0なら秒を省く（例: `2026/07/17(金) 12:34`、秒があれば `2026/07/17(金) 12:34:56`） | 既定ソートキー① |
| 3 | 残り時間 | `fireAt − now` を整形（「2時間30分」等・**整形ルールは §6.2**） | **ソート不可** |
| 4 | コメント | `message` | 既定ソートキー② |
| 5 | Cmd | `action`（発火時コマンド・空可） | 文字列 |

- 列幅の初期値は旧版準拠（Type狭・コメント広）。**終了時に `config.properties` へ永続化
  される**（キー `table.columnWidths`・→ `kReminder_Config仕様_v1.md` §5.6）。
- フォント等外観は kClock2 の Config 流儀を流用してよい。

### 2.4 ソート

- **既定ソート**：次回実行↑（第1キー）→ コメント↑（第2キー）。旧版踏襲。
- **残り時間列はソート不可**（次回実行と一次従属なので無意味・旧版もそうしていた）。
- **Type列は独自比較**：`Pri-N` 文字列を素直に比較すると桁で崩れるため、旧版同様パディングして数値順になるようにする。
- ヘッダクリックでのソート切替は許可。フィルタとソートは独立。

### 2.5 行操作（新規/複製/削除スライスで確定）

- **選択モードは単一選択**（`ListSelectionModel.SINGLE_SELECTION`）。複数選択は対象外。
- **シングルクリック**：選択（`curSce` 相当の「現在行」を保持）。複製・編集・削除の対象。
- **ダブルクリック**：選択行を編集ダイアログで開く。
- 選択なしで 複製／編集／削除 が呼ばれたら**無反応**（旧版準拠・`NULL` ガード）。削除は加えて statusBar に案内を出す（後述）。

#### 2.5.1 新規（`新規` ボタン／Ctrl+N）

- `new Reminder()` を作り、`fireAt` に「現在日時の秒を0に丸めた値」（`LocalDateTime.now(clock).withSecond(0).withNano(0)`）を入れる。他フィールドは `Reminder()` の既定のまま（`priority=Pri3` / `action=""` / `repeat=""`、`message` は空文字にしておく）。
- この `Reminder` を編集ダイアログに渡して開く。**OK なら** `reminders` に追加・保存・テーブルへ行追加を通知（§2.5.4）。**キャンセル/Esc/×なら何もしない**（追加しない）。
- 日時入力ウィジェット（§4.8・別紙v1.1）自体は無改造。新規時のデフォルト値は呼び出し側（`MainWindow`）が用意する。

#### 2.5.2 複製（`複製` ボタン／Ctrl+D）

- 選択行が無ければ statusBar に案内を出して何もしない。
- 選択行の `Reminder` を全フィールドコピーした新インスタンスを作る。**`noticed` は `false` にリセット**。
- **`message`（コメント）だけ** `CopyName.nextCopyComment()` を通して採番する（§2.5.3）。
- 以降は新規と同じ導線（編集ダイアログ → OK なら追加・保存・行追加通知、キャンセル等は何もしない）。

#### 2.5.3 `(copy)` 採番規則（`CopyName.nextCopyComment`・純関数）

コメント文字列の先頭に `(copy)` 系のマーカーを付け足し／カウントアップする。

| 入力 | 出力 | 備考 |
|---|---|---|
| `null` / `""` | `(copy)` | 空扱い |
| `ゴミ出し` | `(copy)ゴミ出し` | 先頭が `(copy...)` にマッチしない→そのまま前置（間に空白なし） |
| `(copy)ゴミ出し` | `(copy2)ゴミ出し` | 番号省略＝1とみなし+1 |
| `(copy2)ゴミ出し` | `(copy3)ゴミ出し` | |
| `(copy9)x` | `(copy10)x` | 桁が増えても本文はそのまま |
| `(copy)` | `(copy2)` | マーカー単体でも同様 |
| `(COPY)` / `( copy )` | `(copy)(COPY)` 等 | 大文字・空白入りは非マッチ＝先頭付与になる（意図どおり） |

正規表現 `^\(copy(\d+)?\)` にマッチするかどうかで「採番済み／未採番」を判定する。

#### 2.5.4 削除（`削除` ボタン／Delete キー）

- 選択行が無ければ statusBar に案内を出して何もしない。
- `JOptionPane.showConfirmDialog`（YES_NO・対象のコメントを本文に出す）で確認し、**「いいえ」なら何もしない**。
  - **コメントが null/空文字の場合は「（コメントなし）」と表示する**（素の値をそのまま出すと「「null」を削除しますか？」になってしまうため）。
- **「はい」**なら `reminders` から該当 `Reminder` を除去・保存・テーブルへ行削除を通知。
- 削除後は選択を解除し、statusBar に削除した旨を表示する。

#### 2.5.5 追加後の見せ方（新規・複製 共通）

- 追加した行（モデル末尾）を `sorter.convertRowIndexToView()` でビュー行に変換する。
- **-1 でなければ**その行を選択し、`scrollRectToVisible` でスクロールして見せる。
- **-1（＝現在のフィルタ条件で非表示）なら**、「追加しましたが現在のフィルタでは非表示です」の旨を statusBar と DEB ログの両方に出す。

#### 2.5.6 キーバインド一覧

| スコープ | キー | 動作 |
|---|---|---|
| テーブル（`WHEN_FOCUSED`・フォーカス時のみ） | Space | instant 起動（選択行の有無に関係なく開く） |
| 〃 | Enter | 編集を開く（JTable既定の「次行へ移動」を上書き） |
| 〃 | Delete | 削除 |
| `MainWindow` の rootPane（`WHEN_IN_FOCUSED_WINDOW`） | Ctrl+N | 新規 |
| 〃 | Ctrl+D | 複製 |
| 〃 | Ctrl+I | instant 起動 |

テーブルの3キーを `WHEN_FOCUSED` に限定するのは、検索欄でのスペース入力・文字削除を殺さないため（window スコープにはしない）。Ctrl+N/Ctrl+D/Ctrl+I は編集ダイアログ・発火ポップアップなど別ウィンドウにフォーカスがある間は発火しない（意図どおり）。

## 3. 表示フィルタ（新モデル）★ 本仕様の核心

### 3.1 設計原則：判定を純関数に切り出す

旧版の失敗は、フィルタ論理が Swing の `RowFilter` に埋まっていたこと。新版では**GUI から完全に切り離した純関数**にする。

```
boolean isVisible(Reminder r, FilterState f, Instant now)
```

- `FilterState` ＝ トグル bool 群＋検索文字列の record（イミュータブル）。
- Swing の `RowFilter` は「この関数を呼ぶだけの薄い皮」。
- `bucketOf()` / `leadWindowOf()` も純関数に切る。
- **RepeatSpec と同じく表駆動で TDD できる**。これが「わけわかめ」再発を防ぐ骨。

### 3.2 判定順（上から短絡）

```
isVisible(r, f, now):
    remain = r.fireAt − now

    # ── 上書き層（バケツチェーンの外・最優先で短絡） ──
    if f.searchText が非空:
        return r.message.contains(f.searchText)   # ← 全トグル無視・ここで確定
    if f.showAll:
        return true                               # ← 全表示ONは無条件

    # ── 独立フィルタAND ──
    if not bucketVisible(remain, f):        return false   # ① 時間バケツ層(内部OR)
    if not priorityVisible(r, f):           return false   # ② 重要度
    if r が繰り返し and not f.showAllRepeat:
        if remain > leadWindowOf(r.repeat): return false   # ③ リードタイム(案Y)
    return true
```

**旧版との決定的な違い：各フィルタを完全に独立させる（互いに干渉しない）。** これが「とっちらかり」解消の核心。

### 3.3 ① 時間バケツ層（残り時間で一意・内部はOR）

各リマインダーは残り時間で必ず1つのバケツに入る。各バケツに表示トグルが1個。**「自分の所属バケツがONなら通過」＝バケツ層内部はOR**、その結果を後続フィルタと AND する。

| バケツ | 範囲（remain） | トグル名 | 既定（提案・要調整） |
|---|---|---|---|
| 終了済 | ≤ 0 | `終了済` | OFF |
| 直近 | 0 〜 8h | `直近` | ON |
| 近日 | 8h 〜 7日 | `近日` | ON |
| 先 | 7日 〜 | `先` | OFF |

```
bucketVisible(remain, f):
    return f.bucketEnabled[ bucketOf(remain) ]

bucketOf(remain):
    if remain <= 0:   return 終了済
    if remain < 8h:   return 直近
    if remain < 7日:  return 近日
    else:             return 先
```

旧版のように時間と繰り返しをここで混ぜない（繰り返しは③で別扱い）。

### 3.4 ② 重要度フィルタ

- トグル `重要度低`：**OFF のとき Pri-1・Pri-2 を隠す**。それだけ。独立。
- 既定 ON（＝低優先も表示）。

### 3.5 ③ 繰り返しリードタイム（案Y）

旧版で一番賢く一番こんがらがっていた部分の正体は、**繰り返し予定を「発火の何時間前から一覧に出すか」という先読み（リードタイム）**だった。月次の家賃予定が3週間先の間は隠れ、直前だけ出る——この「見やすさの妥協点」を、旧版の2トグル＋時間絡みから **1トグル＋自動ルール** に畳む。

- **繰り返し予定は、間隔に応じた先読み窓に入った時だけ表示。窓の外は隠す。**
- 解除トグルは `繰り返し全部表示` 1個（ON でリードタイム制約を無効化。※バケツ・重要度は引き続き効く）。
- **非繰り返し予定はこの制約を受けない**（バケツと重要度だけ）。

```
leadWindowOf(repeat):        # 間隔クラス → 先読み窓
    interval = repeat の有効間隔
    if interval < 1日:   return 3h    # 短期（時/分/秒）
    if interval < 7日:   return 6h    # 日次
    if interval < 30日:  return 2日   # 週次〜
    else:                return 3日   # 月次以上
```

| 間隔クラス | 例 | 先読み窓（この時間前から表示） |
|---|---|---|
| 短期（時/分/秒） | `rep=30`, `rep=6h` | 3h |
| 日次（1〜6日） | `rep=1d`, `rep=3d` | 6h |
| 週次（7〜29日） | `rep=7d`, `rep=15d` | 2日 |
| 月次以上（30日〜/月単位） | `rep=1M`, `rep=12M` | 3日 |

**これらの数値は初期値。** 実機で一度チューニングして固定する類（本人談：一度いい感じに決まれば以後いじらない）。`leadWindowOf` を純関数に切ってあるので後から差し替え自由。

### 3.6 検索の扱い（上書き・状態を壊さない）

- 検索欄が非空になった瞬間、**バケツ・重要度・リードタイムを一切無視してコメント一致のみ表示**（§3.2 最上位で短絡）。旧版の建付けを踏襲。
- 理由：検索は「あの予定どこ行った」を探す局面。そこで時間フィルタが効くと見つからず逆にストレス。検索中はフィルタ解除が正しい。
- **検索は一時的な上書きであり、トグル状態を破壊しない。** 検索欄を空に戻すとトグル状態がそのまま復活する。

### 3.7 永続化

- フィルタの**6トグルの ON/OFF は `config.properties` に永続化**する（次回起動で復元）。
- **検索文字列は永続化しない**（§3.6 のとおり一時的な上書きであるため）。`FilterState` は
  7つの boolean を持つが、`showAll` は UI 未実装のため永続化対象は6つ。
- **キー名・既定値・保存の契機・`Config` クラスの機構は
  `kReminder_Config仕様_v1.md` が正典。** ここは「6トグルを永続化する」方針だけを持つ。

## 4. 編集ダイアログ

### 4.1 用途は2つ（モードではなく「開かれ方」）

| | 通常ダイアログ | instant 入力 |
|---|---|---|
| 開く契機 | `新規` / `編集` / ダブルクリック / `複製` | ポップアップの `Extend`（＝スヌーズ）／クイック追加（ツールバー `instant` ボタン／Ctrl+I／リストで Space） |
| 日時指定 | **日付＋時刻フル**（日をまたぐ予定はこっち） | **時刻のみ・24時間以内限定・日付なし** |
| 秒 | 任意（あれば読む・無ければ0） | 不要（分精度） |

`instant` は「今ここでサッと入れる」用途に特化。日付が要る予定は通常ダイアログで打つ、という住み分け。

### 4.2 フィールド構成（5項目＋プレビュー枠）

旧 `SceEditDialog` を基に整理（`直近`／`Test` ボタンは chat25 で廃止確定・実装にも存在しない）。上から：

1. **実行時刻**（＝ fireAt。通常モードは §4.8 の欄分割ウィジェット、instant モードは §4.4 の書式）
2. **繰り返し**（＝ repeat 生文字列）
3. **優先度**（ドロップダウン：**Pri-1〜Pri-5 のみ**。旧 `Tvr` は入れない）
4. **コメント**（＝ message）
5. **Cmd**（＝ action・空可）
6. **プレビュー枠**（読み取り専用テキスト・下段）

- **Type に Tvr を入れない理由**：発火時コマンド実行は priority と直交させる。**action 欄が非空なら priority に関係なく実行**（v0 §4）。旧 Tvr の役割はこれでカバー。
- ENTER キーで OK（OK が有効なとき）。ESC で Cancel。

### 4.3 ライブプレビュー（旧版の良い設計・踏襲）

- 日時／Rep を打つたびに**プレビュー枠がリアルタイム更新**。
- 内容：
  - 通常ダイアログ ＝ 残り時間表示（§6.2・例「5時間30分」）＋ **次回10回ぶんの発火日時**（`RepeatSpec.next()` を反復）。Rep が不正なら使い方ヘルプ。
  - instant ＝ 残り時間表示（§4.5）。
- **全項目が valid なときだけ OK ボタンが有効**（`isValidExecTime & isValidRep & isValidCmd`）。旧版の三条件踏襲。

### 4.4 時刻入力の書式（instant 入力欄）★確定

**相対か絶対かの判定（3行）**

1. `+` で始まる → **相対**
2. `+` なし ＋ `:` あり → **絶対**
3. `+` なし ＋ `:` なし → **相対**（暗黙の `+`）

**書式（最大3フィールド）**：`[時:]分[.秒]`
`:` ＝ 時と分の区切り、`.` ＝ 秒の区切り。`:` `.` は各1回まで。`.` の後に `:` は来ない。

**桁ルール**：**最上位フィールドのみ1桁以上で自由。それ以外はきっちり2桁**（相対・絶対で共通）
- OK: `1:02.03` / `+05` / `+12345` / `0.25`
- NG: `1:2.03` / `1:02.3`

**値域**
- 区切られた下位フィールド（分・秒）＝ 0〜59（`1.60` はエラー）
- 単独（最上位）フィールド＝上限3日まで自由
- 絶対の「時」＝ 0〜23（`24:00` はエラー）
- **相対の上限 ＝ 3日（72時間）**。超過は文法エラーと区別して専用メッセージ

**単位サフィックス（相対専用の別記法）**
`[時:]分[.秒]` 書式とは別に、「整数＋単位1文字」だけの単純記法も相対として受け付ける：
- 単位は `s`＝秒 / `m`＝分 / `h`＝時（**小文字のみ**。`S`/`M`/`H` は文法エラー）
- 例：`15m`＝15分後 / `30s`＝30秒後 / `2h`＝2時間後 / `90m`＝90分後
- 先頭の `+` は付けても付けなくても同じ（`+15m` と `15m` は同じ）
- 数値部は正の整数のみ（`1.5h` のような小数は不可）
- `:` や `.` との併用はエラー（`1:30m` / `1.30s` は文法エラー）
- 上限は `[時:]分[.秒]` 書式と同じ72時間（超えたら3日超過エラーに合流。例：`73h` / `4321m`）

**秒の扱い**
- 相対：`now`（ナノ秒は捨てる）に Duration を足す＝**now の秒を保持**（`+3` は正確に3分後）
- 絶対：指定秒（省略時は 00 秒）

**絶対の翌日送り**：候補が `now` より後でなければ翌日（now とちょうど同時刻も過去扱い）。エラーにはしない。旧版は「過去の時刻です！」で弾いていたが、これは設計ミス。「12:34にセット」と打つ時、当日ぶんが過ぎていれば普通は翌日のつもり。instant は日付非対応・24時間以内〜数日先限定。翌日送りで十分カバー。

**`+0` / `0`**：即発火として許可（発火テスト用途）。

**入力の正規化**：前後の空白を trim。**全角は半角に変換して受け入れる**
（`０`〜`９`→`0`〜`9`、`＋`→`+`、`：`→`:`、`．`→`.`、`。`→`.`）。内部の空白はエラー。

**エラー時**：OK ボタン非活性。Enter を押すと `SND.play("Oops")`。プレビュー枠に**リアルタイムで文法説明**を出す（繰り返し欄のエラー表示と同じ思想）。

**主な例**

| 入力 | 解釈 |
|---|---|
| `25` | 25分後（暗黙の相対） |
| `+25` | 25分後 |
| `+1:30` | 1時間30分後 |
| `+1:23.45` | 1時間23分45秒後 |
| `+23.45` | 23分45秒後 |
| `0.25` | 25秒後 |
| `+0` / `0` | 即発火 |
| `12:34` | 今日12:34:00（過ぎていれば翌日） |
| `1:02.03` | 今日 01:02:03（過ぎていれば翌日） |
| `1230` | **1230分後**（コロン無し＝相対。`12:30` のつもりの打ち間違いはプレビューの確定日時で気づかせる） |
| `1:2.03` `1:02.3` | エラー（最上位以外は2桁必須） |
| `1.60` | エラー（秒は0〜59） |
| `24:00` | エラー（絶対の時は0〜23） |
| `12345` | エラー（3日超） |
| `+123:45` | エラー（3日超） |
| `+2:` `+:30` `:30` `.30` `。30` | エラー（文法） |
| 空欄 | エラー（文法） |
| `15m` / `+15m` | 15分後（単位サフィックス） |

**`1230`問題への対処方針**：ルールを増やして防ぐのではなく、**§4.5 の補助表示（確定した絶対日時）で気づかせる**（無害化）。「コロン無しは相対」という単純なルールで一貫させ、取り違えは表示で気づく設計とする。

### 4.5 補助表示「残り時間」（本人追加仕様・確定）

- 入力欄の下段に、**打つたびリアルタイムで「○○分」「○時間○分」を表示**（「後」は付けない・§6.2）。
- 「結局この入力だとこれだけ後に発火します」を常時提示することで、`1230` のような取り違えに即気づける。入力ミス防止の要。
- 不正入力（`+` だけ・`99:99` 等）なら「入力エラー」表示＋ OK ボタン無効。
- instant／通常ダイアログの**両方**の下段に出す（通常は残り時間＋次回日時プレビュー、instant は残り時間のみ）。

### 4.6 秒の扱い

- **instant**：分まで（`12:34`）。秒指定なし。
- **通常ダイアログ**：秒は**任意**。`12:34`（→ 00秒）でも `12:34:56` でも受け付ける。「秒はあれば読む、無ければ0」。旧版が秒精度を持っていた（`.sce` の `08_00_00`）ことの踏襲だが、普段は分まででよい。

### 4.7 編集 = 削除 + 追加 / Type = Pri-1〜5

- 既存を編集して OK ＝ **旧を削除して新規追加**（旧 `SceEditModel.create()` 準拠）。実装上のイミュータブル運用。
- Type ドロップダウンは Pri-1〜Pri-5。既定 Pri-3。

### 4.8 実行時刻の日時入力ウィジェット（③-e・確定仕様）

実行時刻欄を単一 JTextField から欄分割ウィジェットに置き換える。目的は「開いたら即・数字の連打で近い日時ほど少ない打鍵で入力できる」こと。

**構成**：`[yyyy]-[MM]-[dd] [HH]:[mm]:[ss]`。6つの表示欄（年4桁・他2桁）＋区切りJLabel。欄は表示専用（手打ちのキャレット編集はさせない）。フォーカス・キャレットとは別に自前の「カーソル」（アクティブ欄）を状態として持ち、背景色等で可視化する。

**初期状態**：編集時は既存値、新規時は現在日時（新規ボタンは未実装＝将来）。ダイアログを開いた時点でカーソルは「日」欄にあり活性。

**打鍵入力**：
- 数字を打つと、その欄の旧値はクリアされ入力バッファが始まる（欄に入っただけでは何も起きない。最初の打鍵でクリア＝再進入リセット）
- バッファは右詰め・未入力上位桁は空白表示（例: 2打鍵→`[ 2]`）
- バッファが欄幅（年4・他2）に達したら値確定・カーソルは右隣へ移動
- 秒欄（右端）で満了したらカーソル消滅（実質確定）

**カーソル移動**：←→キーで隣へ移動。任意の欄クリックで直接指定。Tabではカーソルは点かない。**欄を離れるとき（←→・クリック移動・閉店含む）未完バッファは上位桁ゼロ埋めで欄に確定**（例: 「2」→02）。

**確定操作**：
- Enter＝現欄の未完バッファをゼロ埋め確定し、カーソル消滅。そのままOKを発火して登録完了（v1.2でEnter1回に改訂。OK非活性なら「Oops」で警告）。詳細は日時入力ウィジェット仕様書 v1.2 §3.5参照
- Space＝カーソル欄の入力バッファが活性中（打ちかけがある）なら、その打ちかけをゼロ埋め確定して現欄の値は活かし、下位の欄だけを最小値（月/日=1、時分秒=0）にして確定・カーソル消滅。バッファが非活性（欄に居るがまだ何も打っていない＝再進入直後や自動送り直後）なら、現欄を含めて最小値にして確定・カーソル消滅（例: 「23:45:55」の時欄で「1」「2」と打って分欄へ自動送りされた直後にSpaceを押すと、分自身もクリアされて「12:00:00」になる）。確定後、フォーカスは繰り返し欄へ移る（v1.2）
- カーソル消滅後は欄クリックまで打鍵無効
- 他のコンポーネント（コメント欄等）を触った瞬間もカーソル消滅（＝閉店。未完バッファはゼロ埋め確定）

**↑↓キー／マウスホイール**（対象は常にカーソルのある欄。カーソル無活性時は無反応）：
- まず未完バッファをゼロ埋め確定してから対象欄を±1
- 秒/分＝0-59、時＝0-23、月＝1-12 でリワインド。日＝1〜その年月の実末日（うるう年考慮）でリワインド
- 月・年の変更で日が末日を超える場合は末日にクランプ（例: 1/31で月↑→2/28。ただし超えない場合は保持: 2/28で月↑→3/28）
- 年は±1のみ（リワインド無し）。年↓は2000で停止（それ未満に下げられない）
- **合成値が不正（parseExecTime が empty）の間は↑↓・ホイールとも無効**

**値の合成と検証**：
- ウィジェットは値を修正しない（時25・月13等の不正値もそのまま保持・表示する）
- `getExecTimeText()` は常に `yyyy-MM-dd HH:mm:ss`（バッファ活性中はゼロ埋め解釈で合成）を返す＝既存 EditFormLogic 契約維持
- ★この書式は `EditFormLogic` との内部受け渡し専用。一覧・プレビューの実際の表示書式（`yyyy/MM/dd(曜) HH:mm[:ss]`・`FireAtFormat`）とは別物＝§2.3／§4.5 参照。
- 不正値の検出・エラー表示は既存のライブプレビュー（「時刻入力エラー」）とOK非活性に委ねる
- **parseExecTime に年下限を追加：年2000未満は empty（エラー扱い）**＝年欄の途中Enter（「26」→0026年）がサイレントに合法値として通るのを防ぐ

**OKボタンとの関係**：OK活性 = isTotallyValid かつ カーソル無活性。カーソル活性中はOKは押せない（Enterまたは他項目タッチで閉店してから）。Escは従来どおりカーソル状態に関わらずダイアログキャンセル。Cancel/Esc/×は従来どおり一切書き戻さない。

### 4.9 コメント空の警告

コメントを空のまま登録すると、後で見返したときに何の予定か分からなくなる。OK 押下時に一呼吸置かせる。

**目的**：入力ミスの防止であって、コメント必須化ではない。だから最終的には OK で通す（確認だけ）。

**警告を出す条件（すべて満たすとき）**：

1. Comment が空（null／空文字／空白のみ＝trim 後に空）
2. かつ、次のどちらか一方でも成り立つ（OR）
   - 実行時刻が `now + 5分` **より先**（ちょうど5分後は素通し）
   - Type・Rep・Cmd のいずれかがデフォルトから変更されている
     （デフォルト＝ Type=Pri-3／Rep=空／Cmd=空。空判定は trim 後）

**素通しするケース**：コメント空・実行時刻が now+5分以内・他項目は全部デフォルト。ラーメンタイマーのような雑な一発モノとみなす（本来この用途は④instant を使う想定だが、念のため通す）。

**警告の出し方**：OK／キャンセルの確認ダイアログ。メッセージは `<<注意：コメントが空です>>`。

- OK → そのまま確定（弾かない＝確認だけ）
- キャンセル → 編集ダイアログに留まる（コメントを書き足せる）

**適用範囲**：編集・新規・複製の区別をせず、ダイアログの現在値だけで判定する（3経路とも `EditDialog.onOk()` を通るため実装箇所は1つ）。

**実装**：判定ロジックは純関数 `EditFormLogic.needsEmptyCommentWarning()` に置く（Swing 非依存）。

### 4.10 モーダリティ

- **EditDialog は `DOCUMENT_MODAL`（owner=MainWindow）**。`APPLICATION_MODAL`（旧: `true`）だと、
  編集ダイアログを開いている間に発火した通知ポップアップまでブロック対象に巻き込んでしまい、
  ポップアップは表示されるのに OK が押せない（入力が死ぬ）事故になっていた（旧不具合）。
- **発火ポップアップは非モーダル・owner=null**（`Main.showPopup` が `new JDialog((Frame) null, ...)` で生成。
  Swing が割り当てる共有隠しフレームが一族の根になる）＝ EditDialog とは別ドキュメント。
- 結果：**編集ダイアログ表示中も発火ポップアップは操作できる**。一方 **MainWindow は編集ダイアログを
  閉じるまで操作できない**（＝編集中の行が一覧操作で消える事故を防ぐ、意図的な仕様）。
- `setVisible(true)` は `DOCUMENT_MODAL` でも呼び出し元をブロックする（ネストしたイベントループを回す）ので、
  `MainWindow.onEditButton` / `openEditorForNew` の「開く→閉じたら書き戻す」という同期的な構造は
  そのまま維持される（MainWindow 側は無改造）。
- 【既知の割り切り】発火ポップアップは表示時にキーボードフォーカスを奪う。編集ダイアログのコメント欄などを
  打鍵中にポップアップが出ると、以降の打鍵が編集ダイアログに入らなくなる。実害は小さいと判断して今回は
  対処しない（本人判断）。対処するなら `setFocusableWindowState(false)` 等が候補。
- **⑤ポップアップ配線（Extend・§5.3）**では、ポップアップから開く instant 編集ダイアログの owner を
  MainWindow にすることで、他の発火ポップアップが生きたまま残る。

## 5. priority ↔ 通知 の対応（§4.5/§10 の確定版）

旧 `AlarmMgr.set()` は **priority で通知の振る舞いを振り分けていた**。priority は単なるソート用ラベルではなく**通知エスカレーションのダイヤル**。**5段階をそのまま採用**（本人談：これがちょうど使いやすかったからそうしていた）。

### 5.1 マッピング表（確定シーケンス・通知拡張PR）

priority に紐づくのは**音声ファイルそのものではなく「鳴らし方」**である。「鳴らし方」＝どの音をどの音量で・何ステップ・どう繰り返すかの手順書＝`NotifyPattern`（`sound.NotifyPattern`／`NotifyPatterns`／`Notifier`、詳細は SND仕様書 §11）。Pri ごとの鳴らし分けを増やしたくなったら `NotifyPatterns.forPriority()` の表だけ書き換えれば、`Notifier` も呼び出し元（Main）も触らずに済む設計にする。**音量はすべて 1.0**（音の大小は wav 自体で表現する＝音量パラメータで作り分けない）。

| Type | 鳴らし方（確定） | ダイアログ挙動（`PopupBehavior`） | 備考 |
|---|---|---|---|
| Pri-1 | Small ×1（繰り返しなし） | **5秒で自動消滅**・**Extend ボタンなし**（OK のみ） | 軽い通知 |
| Pri-2 | Notify を **10秒間隔**で繰り返し・最大**5分** | 自動消滅なし・OK / Extend | |
| Pri-3 | Standard を **5秒間隔**で繰り返し・最大**10分** | 自動消滅なし・OK / Extend | 既定 |
| Pri-4 | Standard(待ち0.5秒)×3 → Standard(待ち5秒)×3 → Watchout(待ち5秒)×10 → Watchout(待ち60秒) を以降ずっと繰り返し・最大**2時間** | 自動消滅なし・OK / Extend | |
| Pri-5 | Standard(待ち0.5秒)×5 → Watchout(待ち5秒)×10 → Serious(待ち60秒) を以降ずっと繰り返し・最大**12時間** | 自動消滅なし・OK / Extend | 目覚まし級 |

※「待ちN秒」は `SoundWorker` が再生を終えてから N秒待つ意味（クリップ長は別途加算される）。

`PopupBehavior`（新設・`ken5005.kreminder.gui`）は「自動消滅までの時間（`autoCloseAfter`、null＝しない）」
と「Extend ボタンを見せるか（`showExtend`）」だけを持つ純粋な record＋表（`PopupBehaviors.forPriority`）。
Pri-1 のみ `autoCloseAfter=5秒・showExtend=false`、Pri-2〜Pri-5 は `autoCloseAfter=null・showExtend=true`。

- **旧版のマルチモニタ非依存化**：旧コードの `COMPUTERNAME=="TAKESHI01"` 専用座標ハードコードは排除（v0 §4.5 既述）。

### 5.2 ⑤時点の実装範囲（現況）

⑤ポップアップ配線スライスで実装したのは、全 Pri 共通で「Standard を volume 1.0 で1回」という暫定パターンのみだった。**通知拡張PRで §5.1 の確定シーケンスに到達済み**（Pri ごとの鳴らし分け・自動消滅／Extend非表示・同時発火時の交通整理まで含む）。音源アセット（Notify/Standard/Watchout/Serious/Small の実ファイル）の用意可否は別途。

### 5.3 スヌーズ = Extend = instant 編集ダイアログ（確定）

**専用のスヌーズUIは作らない。** 旧版のスヌーズ機構の正体はこれ：ポップアップの `Extend` ボタン → コメント頭に `(Ext) ` を前置して **instant 編集ダイアログを開く** → `+30` と打って30分後に再登録。

**動線**：発火ポップアップの `Extend` ボタン → `MainWindow.openExtendEditor(fired)` → instant モードの `EditDialog` を開く。

**引き継ぎ規則**：

| 項目 | 引き継ぎ | 備考 |
|---|---|---|
| コメント | `(Ext) ` を前置 | 既に前置済みなら重ねない（`ExtName.hasExtPrefix`） |
| 繰り返し | 引き継がない（空） | Ext は「この回だけ先送り」の単発。元が繰り返しでも引き継がない |
| 優先度 | 引き継ぐ | |
| Cmd | 引き継ぐ | |
| 実行時刻 | 引き継がない | instant モードなので空欄スタート（ユーザーが `+30` 等を打つ） |

**ポップアップの開閉**：編集ダイアログが **OK で閉じて実際に登録されたときだけ**、発火ポップアップを閉じる。**キャンセル／Esc／× なら発火ポップアップは残す**（通知を消さない）。

**最前面の被り対策**：発火ポップアップ・instant 編集ダイアログとも `alwaysOnTop` なので、両方を同時に立てると重なって奥側が読めなくなる。Extend で開く instant ダイアログは `alwaysOnTop` にし、**張本人の発火ポップアップはその間だけ `alwaysOnTop` を降りる**（instant 側が閉じる／キャンセルされたら元に戻す）。

### 5.4 `(Ext) ` 規約（確定）

- **削除条件**：コメントが `(Ext) ` で始まる（`ExtName.hasExtPrefix`）**かつ** repeat が空。両方満たす単発予定だけが削除対象。repeat 付きの `(Ext) ` は削除しない。
- **削除タイミング**：発火した瞬間（`Main.checkReminders`）。
- 発火ポップアップは表示文字列（message）を**コピー済み**で開いているため、リストから該当 `Reminder` が消えても、既に開いているポップアップの表示には影響しない。
- 通常の単発予定（`(Ext) ` が付かない）は発火後 `終了済` として残る（バケツ「終了済」で表示可）。
- **編集中に自動削除された場合**：編集ダイアログを開いている最中に対象が `(Ext) ` 自動削除された場合、**OK で閉じると §4.7「編集＝削除＋追加」に従い新しい行として追加し直す**（statusBar と DEB ログの両方で通知）。**キャンセルなら消えたまま**（何もしない）。

### 5.5 複数同時発火の整列

- 同時刻に複数発火した場合、ダイアログを重ならないよう並べる（旧 `isOccupied[20]`＝最大20枚をずらし配置）。座標は解像度非依存に再設計。
- **同時表示の上限は 10 → 20 に引き上げる**（`MAX_POPUPS`）。

**鳴らすのは1件だけ（通知拡張PRで確定）**：`SoundWorker` は直列1本なので、複数ポップアップが
同時に鳴ると詰まる。よって「継続的に鳴らすのは、開いているポップアップのうち priority が最も
高い1件だけ」とする。

- 後から発火した方が**厳密に** priority が高い場合だけ、鳴らす担当を差し替える（同率なら先着優先）。
- 担当になれなかったポップアップは、自分のパターンの**第1ステップだけを1回**鳴らす（新しい通知が
  来たことに気づけるようにするため）。継続音は鳴らさない。
- 鳴らしていたポップアップが閉じたら、残っているポップアップのうち最優先のものが自分のパターンを
  頭から鳴らし始める（＝担当を引き継ぐ）。
- この不変条件（＝開いているポップアップのうち最優先のエントリが担当）は Main 側で1メソッドに
  集約する（実装詳細は実装計画側）。

### 6.1 `RepeatSpec` 日本語化（`toJapanese()`）★確定

リピート列とプレビューで、`repeat` 生文字列を人間可読な1行にする。`RepeatSpec` に純関数 `toJapanese()` を追加（表駆動で TDD 可）。旧 `RepeatMgr.toString()`（kconpnl）を一次ソースに再解析し、潜んでいた癖を修正した版。

**組み立て手順**：

1. **間隔語**（`rep=` 部）
   - 月（`M`）：`1M→月` ／ **12の倍数→年**（`12M→年`, `24M→2年`）／ それ以外→`Nヶ月`（`13M→13ヶ月`）
   - 日（`d`）：`1d→日` ／ **7の倍数→週**（`7d→週`, `14d→2週`, `21d→3週`）／ それ以外→`N日`（`15d→15日`）
   - 時・分・秒：`1h→時間`/`1m→分`/`1s→秒`、他は `N時間`/`N分`/`N秒`。単位省略＝分。**時分秒はまたいで畳まない**（`24h→毎24時間` のまま。`毎日` にはしない）
2. **絶対日**（`day=N`・月次のみ）：間隔語の後ろに `N日` を足す（`毎月25日`）
3. **繰上**（`kuriage`）：`(繰上)` を付ける。**kuriage は月次専用**（後述）。位置＝絶対日の直後（`毎月25日(繰上)`）、絶対日が無ければ月の直後（`毎月(繰上)`）
4. **週指定**（`dai=`／内部は許可週 `Set`）：**常に表示する**（旧は除外曜日ゼロだと隠していた＝バグ）。`毎週 第1第3週` のように独立トークンで付ける。ただし後述の bare 形では曜日に前置（`第1第3木`）
5. **曜日**（除外 `boolean[7]`・並び順は **月火水木金土日**）：
   - 除外0個 → 曜日トークンなし
   - 除外1〜3個 → `△△除く`（除外曜日を並べる。`毎日 土日除く`）
   - 除外4〜6個（＝許可1〜3個）→ 許可曜日を並べる。**間隔が毎日（`1d`）なら bare 形＝曜日だけ**（`火`, `水土`, dai あれば `第1第3木`）。**毎日以外なら `○○のみ`**（`毎月 火のみ` 等・実データには出ない仮想ケース）
   - 除外7個 → エラー（有効曜日なし）

**bare 形の意図**：`毎日 火のみ` は読みづらいので、毎日＋曜日限定のときは接頭辞を落として曜日文字だけにする（`火`＝毎週火曜の意）。旧の `曜日=火` の代わり（`曜日=` は廃止）。

**kuriage の非月次エラー（コア側の決定・§8）**：`kuriage` の繰上/繰下は月次の除外日回避でしか意味を持たない（`next()` で `unit==MONTH` のときだけ発火）。非月次の kuriage は無意味なので、**`RepeatSpec.parse()` で `unit≠MONTH` かつ kuriage なら `IllegalArgumentException`**（`day=N` が月次必須なのと同じ扱い・原則2「怪しきは罰する」）。これは GUI ではなくコア（仕様ドラフト v0 §3／`RepeatSpec`）の変更＝実装時に v0・CLAUDE.md にも反映する。

**対応表（旧実データ36パターンで検証済み・代表抜粋）**：

| repeat | 日本語化 | 備考 |
|---|---|---|
| `rep=1d` / `rep=7d` / `rep=1M` / `rep=12M` | 毎日 / 毎週 / 毎月 / 毎年 | 基本 |
| `rep=14d` / `rep=21d` / `rep=13M` | 毎2週 / 毎3週 / 毎13ヶ月 | 倍数畳み／端数 |
| `rep=3d` / `rep=6h` / `rep=30` / `rep=1000m` | 毎3日 / 毎6時間 / 毎30分 / 毎1000分 | 数値+単位 |
| `rep=1d;ex=0,6` | 毎日 土日除く | 除外≤3→除く |
| `rep=1d;ex=0,1,6` | 毎日 月土日除く | 〃 |
| `rep=1d;in=2` | 火 | bare（毎日＋曜日限定） |
| `rep=1d;in=3,6` | 水土 | 〃 |
| `rep=1d;in=0,1` | 月日 | 〃（並び順 月…日） |
| `rep=1d;in=4;dai=1,3` | 第1第3木 | 〃＋週指定前置（燃えないゴミ） |
| `rep=7d;dai=1,3` | 毎週 第1第3週 | dai 表面化（旧は「毎週」に化けた） |
| `rep=1M;day=25;kuriage;ex=0,6` | 毎月25日(繰上) 土日除く | 納会 |
| `rep=1M;day=19;ex=0,6;kuriage` | 毎月19日(繰上) 土日除く | 家賃 |
| `rep=1M;ex=0,6;kuriage`（day無し・仮想） | 毎月(繰上) 土日除く | 繰上位置 |
| `rep=1d;kuriage;ex=0`（非月次kuriage） | **エラー** | 上記コア決定 |

### 6.2 残り時間の整形（残り時間列・補助表示）★確定

`残り = fireAt − now`（正のみを整形。**終了済＝0以下は当面 対象外**＝空欄相当。マイナス表示「○日前」は将来検討）。段は残りで一意に決まる。

**段分け**（`日数 = floor(残り / 24時間)`）：

| 段 | 条件 | 書式 | 例 |
|---|---|---|---|
| 日 | 日数 ≥ 5 | `N日` | `5日`, `1234日` |
| 日時間 | 1 ≤ 日数 ≤ 4 | `N日N時間` | `4日23時間`, `3日5時間`, `1日0時間` |
| 時間分 | 日数0 かつ 残り ≥ 5分 | `N時間NN分` | `2時間05分`, `23時間59分`, `45分`, `05分…`→`5分` |
| 分秒 | 残り < 5分 | `N分N秒` | `3分5秒`, `45秒`, `5秒` |

**端数・ゼロ詰めの共通則**：

- **上位の位がゼロ → その位ごと省略**（`0時間45分`→`45分`、`0分5秒`→`5秒`）
- **下位の位がゼロ → 省略しない**（`2時間0分`→`2時間00分`、`3分0秒`→`3分0秒`、`3日0時間`→`3日0時間`）
- **最上位の位は0詰めしない**（`1時間01分`。`01時間` にしない。時間が消えて分が最上位なら `5分`）
- **0詰めは「時間分」段の分だけ**（`2時間05分`）。他の段（分秒・日時間・日）は詰めない
- 「時間分」段では秒を、「日時間」段では時分秒を切り捨て

具体例（確定）：

| 残り | 表示 |
|---|---|
| 3日5時間 | 3日5時間 |
| 3日ちょうど | 3日0時間 |
| 4日23時間 | 4日23時間 |
| 5日1時間 | 5日（日数5→日のみ） |
| 2時間5分45秒 | 2時間05分 |
| 2時間ちょうど | 2時間00分 |
| 1時間1分 | 1時間01分 |
| 45分 | 45分 |
| 5分ちょうど | 5分 |
| 3分5秒 | 3分5秒 |
| 3分ちょうど | 3分0秒 |
| 45秒 / 5秒 | 45秒 / 5秒 |

## 8. 決定事項ログ（なぜこうしたか）

- **フィルタは完コピせず再設計**：旧版は「出す論理」と「隠す論理」が同一関数で殴り合い、作者本人が `わけわかめ` と自認していた。→ 判定を純関数化し、上書き層（検索・全表示）／バケツ層（OR）／独立フィルタ（AND）の3構造に整理。
- **繰り返しは案Y（リードタイム）採用**：旧版の「月次は直前だけ出る」気持ちよさを、2トグル＋時間絡みから1トグル＋自動ルールに畳んだ。案X（純カテゴリ）だとこの使い勝手が消えるため不採用。しきい値は純関数化して後から調整可能に。
- **priority 5段階そのまま**：使いやすかった実績を尊重（実測優先）。ただし音の細部は後回し・雑実装から。
- **絶対時刻の過去→翌日送り**：旧版の「過去エラー」は設計ミスと判断。
- **`1230` 問題はルールでなく補助表示で守る**：ルールを増やすより「○○後」表示で気づかせる方がシンプル。
- **高頻度操作だけトップレベル**：フィルタ高頻度の記憶（実測）を信じ、音試験・今後の雑多機能は右クリックへ。これを恒久方針化。
- **（新規/複製/削除スライス）`複製` はツールバー＋キーバインドに格上げ**：当初案（§2.2 旧版）では右クリック行きだったが、実運用者の実測で「新規と同程度に高頻度」と判明したため撤回。ツールバーの `複製` ボタン＋ Ctrl+D で新規と同格に配線した（§2.5.2）。
- **Type から Tvr 廃止**：発火コマンドは action 欄と直交（非空なら priority 無関係に実行）。
- **（v2）日本語化は旧 `toString()` を素移植せず再設計**：旧 `RepeatMgr.toString()` には4つの癖＝(1) `dai`（第N週）を除外曜日ゼロだと隠す表示バグ（計算は honor するのにラベルが「毎週」に化ける）(2) 毎日＋曜日限定の `曜日=…` 特別接頭辞 (3) 年変換なし（`12M→毎12ヶ月`）(4) `kuriage` 無検査。→ (1) dai は常に表示、(2) `曜日=` 廃止して bare（曜日だけ）、(3) 12倍数→年・7倍数→週に畳む（端数は据え置き）、(4) 非月次 kuriage はエラー、に整理（§6.1）。
- **（v2）kuriage は月次専用＝コア側の決定**：`next()` の繰上/繰下は `unit==MONTH` でしか発火しない（非月次では黙って無視・デッドロックもしない）。無意味な入力を通すのは原則2に反するので、`RepeatSpec.parse()` で非月次 kuriage を弾く。**これは GUI ではなくコア（v0／`RepeatSpec`）の変更**。実装時に v0・CLAUDE.md へ反映。
- **（v2）曜日の並び順＝月火水木金土日**（旧踏襲。`ex=0,6` は「土日除く」。v1 に「日土」と書いていたのは誤り）。
- **（v2）残り時間整形の確定**：4段（日／日時間／時間分／分秒）、上位ゼロは位ごと省略・下位ゼロは残す・最上位は0詰めしない・0詰めは「時間分」段の分だけ（§6.2）。境界は日数5以上で「○日後」。
- **（v2）EditDialog を `APPLICATION_MODAL` ではなく `DOCUMENT_MODAL` にした**：owner=null の発火ポップアップを
  別ドキュメントとして生かしたまま（編集中も操作できる）、MainWindow へのブロックと「開く→閉じたら書き戻す」
  という同期的な構造（§4.10）は保つため。
- **（⑤）Extend の実処理を `MainWindow` 側に置いた**：(a) `EditDialog` の owner が自然に `MainWindow` になる
  （`DOCUMENT_MODAL`） (b) 「開く→OKなら書き戻し→addReminder→store.save→revealAddedRow」という新規／複製と
  同じ一本道を再利用できる (c) 「行の増減は `ReminderTableModel` に閉じる」原則（CLAUDE.md）を守れる。
- **（⑤）priority に紐づけるのは音声ファイルではなく「鳴らし方（`NotifyPattern`）」にした**：Pri ごとの
  鳴らし分けを増やすとき（エスカレート音・鳴り続け等）、`NotifyPatterns` の表だけ書き換えれば済むように
  するため（§5.1）。
- **（⑤）モーダルダイアログを挟んでモデル行 index を持ち越さない**：`reminders` は EDT 専有（触るのは
  `MainWindow` の各ハンドラと `Main.checkReminders`＝Swing Timer だけで、いずれも EDT 上）なのでロックは
  不要。ただし `setVisible(true)`（モーダル）や `JOptionPane.showXxxDialog` は呼び出し元をブロックしたまま
  内部でネストしたイベントループを回すため、その間も1秒 Timer は動き続け `checkReminders` が走りうる。
  `(Ext) ` 自動削除でリストが縮む経路ができたことでこの stale index 問題が顕在化したため、ダイアログが
  閉じた後は `reminders.indexOf(r)` の参照一致で行を引き直す運用に統一した（§5.4）。

**旧版から意図的に変えた点**：過去エラー→翌日送り／`COMPUTERNAME` 依存座標の排除／フィルタ論理の全面再設計／action を列と priority から独立させた／マルチモニタ非依存／**（v2）日本語化の dai 隠しバグ修正・`曜日=` 廃止・年/週の倍数畳み・非月次 kuriage をエラー化**。
