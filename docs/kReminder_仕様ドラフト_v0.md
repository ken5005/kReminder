# kReminder 仕様ドラフト v0

最終更新: 2026-06-24
位置づけ: 旧自作リマインダー（`kconpnl` の `scedule` サブシステム）の要件を全期間データから棚卸しし、クリーンに再設計した**新規プロジェクトの初版仕様**。実装前の設計フェーズ成果物。

---

## 0. このドラフトの背景（なぜ作り直すか）

- 旧版 `kconpnl` は時計・CPU・ドライブ容量・ブラウザ・カレンダー・メッセージログ・リマインダーの全部入りコントロールパネル。今回サルベージ対象は **リマインダー（`scedule/`）と祝日テーブル（`calendar/`）だけ**。
- 旧版の仕様は「使いながら必要に迫られて足した」結果で構造が整っていない。ただし裏返すと**実運用で本当に必要だった要件の鉱脈**。bak 全世代（計184件の `.sce`）を調べ、末期スナップショットでは見えない過去の使い方（第N週指定・毎月固定日・繰り上げ・発火コマンド）を復元した。
- 方針：**コードは移植しない／要件は全部サルベージする**。汚い実装を忠実に再現させない（実装前の仕分けが価値）。

## 1. スコープ / プロジェクト構成

- **新リポジトリ**（`kReminder` 的な名前）で新規に立てる。git/Claude Code のゼロからのリポジトリ作成練習も兼ねる。
- **時計アプリ（kClock2）は v0.6 完成品として温存**（タグ打って保存）。リマインダーが完成したら、最終形として**一つの常駐窓に統合**する（最終形は「画面のあちこちに自作アプリが散らばらない」状態）。統合作業自体は後フェーズ。
- 時計のコード資産（枠なし窓・最前面・ドラッグ・Config）は**コピーして土台に流用**できる。
- 言語: Java 18。ビルド: Gradle。**初の外部依存（Gson）が出るため shadowJar**（kClock2 が依存ゼロで素の jar だったのと対照的）。

## 2. データモデル（リマインダー1件）

旧 `Scedule` の6フィールドを継承しつつ、現代化する。

| フィールド | 型（概念） | 説明 | 旧 .sce 由来 |
|---|---|---|---|
| `fireAt` | 日時（ISO-8601, `java.time`） | 発火日時 | 1列目 |
| `message` | 文字列 | 通知メッセージ | 6列目 comment |
| `priority` | 列挙（Pri-5〜Pri-1） | 優先度。**旧 `Tvr` 種別は廃止**（→ 移行時に Pri に丸める） | 4列目 typeStr |
| `action` | 文字列（任意・空可） | **発火時に実行する任意コマンド**（`system()` 相当）。空なら通知のみ | 5列目 commandStr |
| `noticed` | 真偽 | 通知済みフラグ | 2列目 isNoticed |
| `repeat` | 文字列（任意・空可） | **繰り返し文法の生文字列**（後述）。空なら一回限り | 3列目 |

- 実行時の状態（Pending / Alarm / Done。旧 State パターン相当）は**永続化しない派生状態**。`fireAt` と `noticed` と現在時刻から導出する。
- 繰り返し指定があるリマインダーは、発火後に `repeat` から次回 `fireAt` を計算して `noticed=false` に戻す（旧 `restart()` 相当）。

## 3. 繰り返し文法（フルサポート）

旧 `RepeatMgr` の文法を**全部そのまま採用**（実データで全機能が使われていたため削らない）。`;` 区切りの命令列。

### 文法

| 命令 | 意味 | 例 |
|---|---|---|
| `rep=Nu` | **必須**。間隔。u は単位 `M`(月)/`d`(日)/`h`(時)/`m`(分)/`s`(秒)。**単位省略時は分** | `rep=3d`（3日毎）, `rep=6h`, `rep=1000m`, `rep=30`（=30分） |
| `ex=曜日,...` | 除外曜日（**日=0** 〜 土=6）。複数可 | `rep=1d;ex=0,6`（平日のみ） |
| `in=曜日,...` | 指定曜日のみ（ex の逆） | `rep=1d;in=4`（木のみ） |
| `dai=週,...` | 第N週のみ（月内の週番号） | `rep=1d;in=4;dai=1,3`（第1・第3木曜＝燃えないゴミ） |
| `day=N` | 毎月N日（`rep=NM` と併用必須） | `rep=1M;day=25`（毎月25日） |
| `kuriage` | 除外日に当たった時、繰り下げでなく**繰り上げ**（前の有効日へ） | `rep=1M;day=25;kuriage;ex=0,6`（毎月25日・土日祝なら前の平日） |

### デフォルト挙動（重要）

- **除外日に当たった時のずらし方**：
  - 間隔系（`rep=Nd` 等）で除外日に当たる → その間隔のまま次へ進み続ける（旧実装通り）。
  - 月固定日系（`day=N`）で除外日に当たる → **デフォルトは繰り下げ（翌日方向）**、`kuriage` 指定時のみ繰り上げ（前日方向）。
- **祝日は除外日扱い**：`ex` に曜日を入れていなくても、祝日判定が true の日は「日曜と同じ＝除外日」として扱う（旧 `CalendarSpecialDayTbl.isHoliday()` と同挙動）。→ 第5節の祝日サブシステムに依存。

### 文字列が「正」（single source of truth）

- 繰り返し指定は**生文字列のまま保持・永続化**する（再パースして分解保存はしない）。移行データ（`rep=1M;day=25;kuriage;ex=0,6` 等）もそのまま乗る。
- 必要な実装は **パーサ（文字列→構造→次回発火日時計算）** と **ビルダー（構造→文字列）** の両方。旧版はパーサしか無かったが、GUI 化のためビルダーが要る。
- 手打ち文字列は**入力時に常にパース検証**され、無効ならその場で弾く（旧版は保存時まで気づきにくかった点の改善）。

## 4. 発火アクション

- リマインダー発火時、`action` が空でなければ**任意のコマンドラインを実行**（Perl の `system("...")` 相当）。
- **エラー隔離（最重要）**：アクションのエラーは**アプリ本体から完全に隔離**する。
  - コマンドは別プロセスで起動し、例外は try/catch で捕捉。
  - **アクションが失敗・エラー終了しても、リマインダーの通知自体は必ず成立する**（鳴る・表示される）。
  - アプリ本体（常駐ループ・他のリマインダー）には一切波及しない。**アクション失敗でアプリが落ちる/リマインダーが消えることは無い**。
- 実行結果（成功/失敗・exit コード・stderr）は**ログに残す**＋失敗ならステータス表示に反映。
- 思想：**「アクションが死んでも通知は生きる」**。

## 4.5 通知（アラームポップアップ）の挙動 — 旧版調査結果＋初版方針

旧版 `Alarm.java` は `Alarm` を基底に**通知の振る舞いを4種のサブクラス**で持っていた（実装精読済み）。初版で全部やる必要はないが、要件として記録する。

### 旧版が持っていた通知タイプ
- **自動消滅型（`AlarmDisappear`）**: OK ボタンのみ。**5秒で自動的に消える**軽い通知。
- **コマンド実行型（`AlarmExecCommand`）**: 自動消滅型＋発火時にコマンド実行（`ProcTVR.exec()`）。TVR がこれ。→ 新版では第4節の汎用「発火アクション」に統合済み。
- **OK/Extend 型（`AlarmOkExtend`）**: OK と **Extend** の2ボタン。**Extend を押すとスケジュール編集ダイアログがその場で開き、内容を編集して再登録できる**（コメントに `(Ext) ` を前置）。＝「ポップアップから直接スケジュールを書き換える」挙動。旧 `.sce` をその場で書き換える動作はこれ。
- **鳴る目覚まし型（`AlarmOkExtendMez`、Mez=目覚まし）**: OK/Extend 型＋**音が段階的に大きくなる**（`Alarm small`→`norm`→`big`→`big`×2 とエスカレート、最大秒数まで繰り返し）。OK/Extend を押すと鳴り止む。音源は旧 `!data/wav`（=今回ゴミ指定したフォルダだが、実体はアラーム音素材）。
- **複数同時発火**: ダイアログを**最大20個まで位置をずらして並べる**（`isOccupied[20]`）。複数リマインダーが同時刻に発火するケースに対応。
- 注: 旧コードに `COMPUTERNAME=="TAKESHI01"`（実家/八幡PC）専用の座標ハードコードあり。新版では当然排除（マルチモニタ/解像度非依存にする）。

### 初版（v1）の方針
- **最小実装**: 「メッセージ表示＋OKで消す」＋「発火アクション実行（第4節）」。これだけでコア成立。
- それ以外（スヌーズ／その場編集／鳴る目覚まし／自動消滅／複数同時並べ）は**初版では見送り可。下記 TODO に積む**。

## 5. 祝日サブシステム

「平日のみ」「毎月N日・土日祝なら前後の営業日へ」等を正しく動かすための祝日判定。

### データソース（内閣府 CSV・実物確認済み 2026-06）

| 項目 | 実態 |
|---|---|
| URL（primary） | `https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv` |
| URL（fallback） | `https://www8.cao.go.jp/chosei/shukujitsu/shukujitsu.csv`（過去に y↔h で揺れた実績） |
| 文字コード | **Shift_JIS（MS932 / windows-31j）** |
| 形式 | ヘッダ行＋`YYYY/M/D,名称` の2列・CRLF |
| 日付 | スラッシュ・ゼロ埋めなし（過去にハイフン/ゼロ埋め有の時期あり） |
| 収録範囲 | 1955年〜**当年+1年**（遠い未来は無い） |
| 内容 | 祝日＋振替休日・国民の休日も込み（除外用途には好都合） |
| ライセンス | CC-BY |

### 公開 API

- `boolean isHoliday(LocalDate)` 一つだけ。繰り返しエンジンはこれを「除外日（=日曜相当）」判定に使う。

### 3層構造

1. **キャッシュ層**: `%APPDATA%\kReminder\holidays.json`（CSV を正規化した `[{date, name}]`）。起動時はまずこれを読む。「最終検証成功日時」も併せて保存。
2. **更新層**: キャッシュが無い / 古い（例: 30日超）/ 当年が入っていない、いずれかの時だけ CSV を DL（`java.net.http.HttpClient`＝標準API・外部依存ゼロ）→ MS932 デコード → パース → 検証 → JSON 保存。**更新トリガーは起動時のみ**（年1更新のデータなので常駐中の定期チェックは不要）。
3. **手動オーバーライド層**: `%APPDATA%\kReminder\holidays-override.json`（ユーザーが手編集）。公式データの上に薄く重ねる。会社の創立記念日・個人的な休み・「この祝日は無視したい」等を追加/削除。**v1 に含める**。

### 検知 → 縮退 → 通報（堅牢性の肝）

**思想：自動では賢ぶらない／怪しきは罰する／最後の正常データで粘る／証拠を残して人を呼ぶ。**

**(1) 検知（ゆるいパース・厳しい検証）**
形式の揺れ（`/` も `-` も、ゼロ埋め有無）は吸収する。が、中身が妥当でなければ**成功扱いにしない**。チェック項目：
- HTTP ステータス 200 以外（404＝ファイル名がまた変わったサイン）
- 取得サイズが極端に小さい（数百バイト＝エラーHTMLの疑い。正常は約20KB）
- 1行目がヘッダ体裁か（`国民の祝日` 等を含むか）
- 各データ行が `日付,名称` の2列・日付がパース可能か
- 件数が妥当か（例: 50件未満は異常。正常は数百〜千件超）
- **当年の祝日が最低数件あるか**
- 元日(1/1) など鉄板の祝日が含まれるか（サニティチェック）

→ どれか1つでも引っかかれば、その取得データは**採用しない**。

**(2) 縮退（採用順位）**
1. 今回 DL した正常データ（検証パス時のみ）
2. ダメなら → **前回の正常キャッシュ**（普段はこれで無停止）
3. それも無いなら → **祝日連動オフに縮退**（土日判定だけは確実に動く）

→ 最悪でも「祝日を見落とすかもしれないが鳴る」側に倒す。「データが怪しいからアラーム停止」は**やらない**。

**(3) 通報（握りつぶされないルート）**
- **トレイ/アイコンに常時ステータス表示**：緑（最新・正常）/ 黄（キャッシュで稼働中・更新失敗）/ 赤（祝日連動オフに縮退中）。
- `%APPDATA%\kReminder\log\holiday.log` に詳細（いつ・どのチェックで・何バイト・どんな中身か）。
- 黄/赤になったら**起動時に一度だけ目立つ通知**（「OK」で消せる）。
- **失敗時の生データを1個だけ残す**：`%APPDATA%\kReminder\holiday-raw-failed.csv`。→ これと `holiday.log` を渡せば「内閣府がまた列を増やした」「ファイル名が shukujitsu に変わった」等を即診断してパーサを直せる（＝将来の自分への手土産）。

## 6. 保存形式

- **単一 JSON ファイル**にリマインダー全件をリスト保持（旧版の「1件=1ファイルの `.sce`」を廃止）。`%APPDATA%\kReminder\reminders.json` 想定。
- **Gson**（または Jackson）でシリアライズ。**UTF-8**。
- 旧版の「ファイル名にデータを埋め込む」方式・Shift_JIS・`java.util.Calendar` は全廃。`java.time` に統一。

## 7. 移行ツール（旧 .sce → 新 JSON）

- **単発の変換ツール**（常駐アプリに移行機能は組み込まない）。`.sce` フォルダを食わせて `reminders.json` を吐く。
- **対象は旧 .sce 全件**（最新＋bak 全世代）。動作チェックの実データになる＆「燃えるゴミの日」等は現役で有用。
- **忠実な形式変換に徹する**（コマンドが生きてるか死んでるかは実行時の問題＝移行時に判断しない）。例外は下記 Tvr の人間指定ルールのみ。

### 変換規則
- **文字コード**: Shift_JIS → UTF-8。文字化けは移行失敗として弾く。
- **6フィールド対応**: 日時/通知済み/繰り返し/種別/コマンド/メッセージ → JSON 各キー。`(empty)` は空文字へ戻す（旧 `save2str` の逆）。
- **繰り返し文字列はそのまま保持**（新エンジンが同文法を解釈するため再パース不要）。
- **Tvr 種別の無害化（人間指定ルール）**: 旧データでコマンド欄を使っていたのは**全件 Tvr 種別**（最新＋bak 全世代で16件、Tvr⇔コマンド有りが1対1）と実データで確認済み。本人が「TVR はもう実行しない」と判断したため、**移行時に Tvr のコマンドへ `echo ` を前置**して無害化（例: `tvr ch=231 setch mentalist` → `echo tvr ch=231 setch mentalist`）。実行しても echo なので死なず、元の内容は echo 引数として記録に残る。**種別 Tvr は Pri（既定 Pri-3 相当）に丸めて廃止**。echo 前置は **Tvr 種別のものだけ**（他種別はコマンド空なので対象なし）。
- **パース失敗行は黙ってスキップせず報告**（何件中何件成功・失敗したのはどれ）。

## 8. GUI（繰り返し入力）— 方針のみ、詳細は別途

- 旧版は `rep=1M;day=25;kuriage;ex=0,6` を**手打ち**していた（GUI が難しいので文字列入力にした、が理由の一つ）。
- 新版は **C案＝プリセット＋カスタム文字列** を採用：
  - 「毎日」「毎週」「平日のみ」「毎月N日」「第N週の曜日」等の**よく使うパターンをプリセット**で選べる（実データのパターンはここでほぼカバー）。
  - プリセットから外れる複雑な指定は**文字列を直接手打ち**（パワーユーザー運用を残す）。
- **文字列とGUIは双方向**：GUI 操作 → 文字列生成、文字列入力 → GUI 反映。文字列が常に正。
- 具体的なウィジェット構成・画面レイアウトは**コア（データ・文法・エンジン）が固まってから別途設計**。

## 9. 設計思想（全体を貫く原則）

1. **自動で賢ぶらない**：壊れたら勝手に推測でリカバリせず、人間（と AI）に投げる。中途半端な自動復旧が一番危険。
2. **怪しきは罰する**：形式の揺れは吸収するが、妥当性が怪しいデータは採用しない。
3. **最後の正常データで粘る**：縮退してでも常駐機能（通知）は止めない。
4. **証拠を残して人を呼ぶ**：ログ＋失敗時生データ＋ステータス表示で、後から原因を即診断できるようにする。
5. **エラーは隔離する**：発火アクションの失敗・祝日更新の失敗が、アプリ本体や通知本体を巻き込まない。

## 10. 未決事項 / 次の段階

- **GUI 詳細設計（C案の具体化）**：プリセットの顔ぶれ、ウィジェット、レイアウト。コア確定後に着手。
- **リポジトリ名**の確定（`kReminder` 的な何か）。
- **優先度（Pri-N）の使い道**：旧実データは Pri-1/Pri-3 中心。表示順・色・通知の強さに反映するか、単なるラベルか。
- **通知（アラームポップアップ）の拡張 TODO**（旧版にあった機能。初版は最小実装＝OKで消すだけ、で可。以下は段階的に検討）:
  - **スヌーズ**: N分後に再通知。旧版に明示的なスヌーズボタンは無かったが（Extend が近い）、本人の記憶通り欲しい機能。実装するなら通知に「スヌーズ(N分)」ボタン＋一時的な再発火予約。
  - **その場編集（Extend 相当）**: ポップアップから直接スケジュール編集ダイアログを開き、内容を変更して再登録（旧 `.sce` 書き換え相当）。「もっと派手にスケジュール内容を変えられる」要件はこれ。
  - **鳴る目覚まし（エスカレート音）**: 段階的に音量/音種を上げ、最大秒数で停止。要・音源アセット（旧 wav 相当を用意するか決める）。
  - **自動消滅通知**: 一定秒で勝手に閉じる軽い通知タイプ。
  - **複数同時発火の整列表示**: 同時刻に複数発火した時にダイアログ/通知を重ならないよう並べる。
- **通知の基本様式**: モーダルダイアログ / OSトースト / 音、のどれを基本にするか（旧版はモーダルダイアログ）。
- **アラーム音の扱い**: 旧 `!data/wav`（今回ゴミ指定）の音源を流用するか、新規に用意するか、鳴らさないか。
- **時計との統合フェーズ**：リマインダー完成後。一つの常駐窓に時刻表示とリマインダーを同居させる。
- **発火アクションのセキュリティ**：任意コマンド実行＝強力。自分専用ツールなので可だが、将来配布する気があれば要検討（今回はスコープ外）。
